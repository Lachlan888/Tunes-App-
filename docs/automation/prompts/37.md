# Prompt 37 — Visual editing and small defects

**Goal:** Make the existing warm design feel intentional through careful subtraction and consistent layout, without adding interface layers.

## Requirements

1. Audit every primary route and its key detail page for adjacent borders, double/triple divider lines, repeated headings/labels, inconsistent padding, low-contrast secondary text, overlarge cards, empty whitespace and floating-control collisions. The supplied Home crops are a required regression example: `MobilePanel` + `MobileStatGrid` + adjacent `MobilePanel` in `components/home/HomeMobileSummarySwitcher.tsx` currently stack horizontal rules.
2. Use one section boundary and one sensible space between adjacent blocks. Preserve functional grouping. Reduce decorative all-caps eyebrows and unnecessary card outlines; keep one focal action per screen.
3. Keep the existing semantic palette and typographic character, but apply state colour only where it means something. List-card colour must not vary merely by database ID. Keep predictable focus, touch and zoom behavior.
4. Keep Help & feedback visible during beta; position it in relation to the phone navigation and any active practice controls so it never obscures them.
5. Treat Practice Diary, Focus Areas and tune index/history as one self-contained secondary workspace with local navigation. Outside it, offer one account-menu entry and an optional end-of-session invitation when the user's existing Diary preference is on. Keep Done as the clear exit. Preserve deep links, privacy, and preference-off behavior.

## Chunks

- **P37-01 — Shared layout rules and Home triple-divider fix.** Establish a small repeatable border/spacing rule in existing components, fix the exact Home stacked-rule defects, and add a focused regression check for adjacent boundaries.
- **P37-02 — Home, Lists and primary-route polish.** Apply the rule to Home, Practice, Tunes, Lists, Social and Compare; remove duplicate labels and awkward joins without changing state or navigation. Check the supplied mockups against rendered structure through targeted automated DOM/style checks. Owner performs final visual judgment.
- **P37-03 — Detail and secondary-route pass.** Review tune/list details, Reference, Trends, Badges, Setlists and owner-enabled Festival. Fix demonstrated repeated chrome, raw dates and overlap; leave unaffected routes alone. Record a route-by-route checklist and remaining owner-owned visual acceptance.
- **P37-04 — Practice Diary workspace.** Consolidate Diary, Focus Areas and tune history behind one account-menu entry and local Diary navigation. Keep other entry points out of everyday chrome; show a preference-gated, dismissible invitation after a saved session. Test direct links, preference on/off, Done/decline, privacy and phone layout.

Prefer scoped edits over a broad CSS rewrite. No new dock, visual framework or decorative animation. Each chunk writes evidence and its successor.
