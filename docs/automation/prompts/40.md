# Prompt 40 — Measured performance and accessibility

**Goal:** Remove demonstrable waiting and accessibility friction in the redesigned journeys without speculative infrastructure work.

## Requirements

1. Collect comparable baseline and after measurements for Home, Practice start/save/next, Tunes search/detail, Lists, Compare and festival Off. Profile root navigation counts, Home fanout, Lists full reads, catalogue facets/media and Compare repertoire reads. Identify the measured bottleneck before changing caching, SQL or component boundaries.
2. Read-only routes should avoid unnecessary writes. Fetch what the visible route needs, keep pagination bounded, and lazy-load heavy media. Retain privacy and freshness when changing query timing. Validate any new index or RPC against actual schema/query plans.
3. Keyboard/screen reader/zoom/reduced-motion support must cover search, tune actions, practice ratings, feedback, lists and Compare. Check 390px phone and larger layouts for no clipped or overlapped controls. The owner remains responsible for manual visual/device acceptance; agents use targeted automated checks and report limits.

## Chunks

- **P40-01 — Performance evidence and targeted fixes.** Measure named journeys, change only the top proven costs, record before/after timings, row/query counts and any freshness trade-off. Add database tests if query semantics or policies change.
- **P40-02 — Accessibility and resilience.** Run focused automated a11y and interaction checks; fix demonstrated focus, labels, announcements, touch, zoom, reduced-motion, loading, refresh and retry defects. Confirm feedback remains visible and non-obstructing.

Do not add a cache, materialized count or new library merely because it is fashionable. Each chunk writes result and next item.
