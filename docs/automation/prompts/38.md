# Prompt 38 — Tune and list workspaces

**Goal:** Make finding, understanding, and organising a tune fast and legible.

## Requirements

1. Preserve server pagination, filters, personal status, list membership, Preview, add-to-list, add-to-practice and Known actions. Reduce equal-weight button noise where it obscures scanning. A row's primary action must be unambiguous; all secondary actions remain discoverable and accessible.
2. Tune detail has exactly two views: **Info** and **Reference**. Info holds identity, contextual next action, personal state/history, notes, catalogue facts, provenance, aliases, attributed sources and folklore (informant, collector, region, story), related tunes, public lists and community discussion. Preserve contributor attribution, privacy, reporting and moderation for all migrated content. Reference owns playback, recordings and passage loops. Do not duplicate its player on Info, retain a third Overview/About tab, or let an empty notes field consume the first screen. Show Stage/day interval and due date only when the tune is in Practice. Redirect old view links deliberately.
3. Lists are neutral organisers. Make title, owner, tune count, purpose and playing order easy to scan. Remove database-ID-based decorative card colour. Distinguish owner Manage from reader Open. Keep private/shared/public visibility and return navigation intact.
4. Keep `Learning Queue` semantics honest: it is derived from saved list items unless the user explicitly chooses a new intent model. A copy change should explain the derivation without silently moving or deleting data.

## Chunks

- **P38-01 — Tunes catalogue.** Tighten row hierarchy, search/filter/result copy, action semantics, loading/empty states and phone width behavior. Test Known/In Practice/new states, long titles and pagination.
- **P38-02 — Tune Info and Reference.** Consolidate the existing Practice/About content into Info with attributed sources and folklore; put the full player and passage tools only in Reference. Format dates, shrink empty notes prominence, preserve media loop/persistence behavior, and redirect legacy view links. Test no media, multiple references, playback failure, personal states and return path.
- **P38-03 — Lists and list detail.** Compact overview, playing-order detail, owner versus visitor controls and neutral queue copy. Test private/shared/public permissions, filter/return, empty list and long names.

Work through existing components; no new catalogue, queue or list subsystem. Each chunk records checks and next item.
