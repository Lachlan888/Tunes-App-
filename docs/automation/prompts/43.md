# Prompt 43 — Contextual action menus

**Goal:** Replace repeated equal-weight secondary action strips with consistent, accessible contextual menus while keeping each surface’s primary task, current state and navigation obvious.

## Requirements

1. Treat this as an interaction task independent from P42 copy reduction. Follow [`docs/design/COPY_AND_CONTEXT_MENUS.md`](../../design/COPY_AND_CONTEXT_MENUS.md) and adopt P42 results without reopening copy work unless menu interaction exposes a concrete defect.
2. Keep predictable title links to tune/list/person/detail destinations. Use a visible disclosure or overflow trigger; right-click and long-press may enhance but never provide the only access. A row may open a preview only when that interaction is consistent, indicated and keyboard accessible.
3. Keep current relationship, Stage/due, unread, visibility, selected source, list position and collaborator state visible outside menus. A state mark may open a focused state menu without losing its visible meaning.
4. Standardise menu ordering: open/view, play/reference, organise, personal state, contribute/manage, then visually separated destructive actions. Permission-gated actions appear only to authorised users.
5. Desktop uses an anchored menu; touch layouts may use a bottom sheet with the same capabilities. Support correct semantics, trigger state, keyboard opening/navigation, Escape/outside dismissal, focus return, touch targets, zoom, reduced motion, pending/success/failure announcements and recovery.
6. Keep Start/Resume Practice, Rough/Shaky/Solid, search/active filters, active form submission, invitation decisions, primary playback transport, Info/Reference switching, empty-state primary actions and beta feedback visible.

## Chunks

- **P43-01 — Shared menu pattern and tune actions.** Establish or consolidate the shared adaptive action-menu primitive using existing modal/menu patterns. Apply it first to catalogue/repertoire tune rows, tune relationship actions, Tune Info Manage and Reference source actions. Preserve preview, list, Practice/Known, contribution/moderation, return and permission behaviour.
- **P43-02 — Collection, people and secondary menus.** Apply the pattern to Lists/public lists/list tunes, Setlists, Social/profile/friend rows, Activity, Inbox, Focus areas, Badges, shared lists and appropriate admin records. Keep direct row navigation and each surface’s primary decision visible.
- **P43-03 — Interaction and parity gate.** Verify menu completeness against pre-P43 action inventories and test mouse, keyboard, touch-sheet, focus restoration, dismissal, pending/error recovery, destructive separation, long labels, clipping/scrolling, narrow phone, tablet, desktop and role-gated states. Fix demonstrated regressions and record owner manual acceptance separately.

Do not create bespoke menu behaviour per route when a shared primitive and action model will work. Each chunk records action parity, interaction checks and next item.
