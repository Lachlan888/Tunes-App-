# P30-01 — Direct suggested-friend comparison

## Accepted

Suggested-friend actions now target the exact friend instead of opening the generic picker. The action reads **Compare** for a first peer and **Add to comparison** for an existing group. Duplicate peers and the seven-peer limit produce disabled **Already added** / **Comparison full** states. Pending navigation disables repeated submission, while the server loader remains the authority for current friendship/consent and continues to block before repertoire reads when eligibility has changed.

Active tune filters, practice scope and overlap group are preserved when a suggestion updates the comparison; result paging intentionally resets for the changed participant set. The generic **Add person/Add musician** picker remains separately available. The desktop suggestion surface and the mobile picker’s suggestion rows share the same action-state rules.

## Changed

- `lib/compare-suggestion-action.ts`: shared exact-target label, duplicate and capacity rules.
- `components/compare/CompareMobile.tsx`, `CompareSuggestionsSection.tsx`, `MobileCompareAddPersonSheet.tsx`, `CompareDesktop.tsx`: direct filtered comparison navigation.
- `components/PendingLinkButton.tsx`: explicit disabled support in addition to transition pending state.
- `tests/compare-suggested-friend.test.ts`: first/add, duplicate, full-group and direct-wiring regression coverage.
