# P27-a — Contribution enforcement and field matrix

## Field policy matrix (recorded before implementation)

| Field or relationship | Canonical policy | Valid empty value | Contribution rule |
| --- | --- | --- | --- |
| `key` | Shared tune detail | `NULL` or blank text | First signed-in valid key fill wins; later changes require moderator/admin. |
| `style` | Shared tune detail backed by active `styles.label` | `NULL` or blank text | First signed-in active-style fill wins; later changes require moderator/admin. |
| `time_signature` | Shared tune detail | `NULL` or blank text | First signed-in `digits/digits` fill wins; later changes require moderator/admin. |
| `composer` | Shared About attribution text | `NULL` or blank text | First signed-in nonblank fill wins; later changes require moderator/admin. |
| `reference_url` | Shared About/reference metadata | `NULL` or blank text | First signed-in HTTP(S) URL fill wins; later changes require moderator/admin. |
| `title`, `alternate_titles`, `type`, `notes` | Established canonical identity/About fields | Field-specific; `title` is never empty | Correction-only for moderator/admin; they are not opened by the fill-once service. |
| `composer_user_id` | Canonical profile relationship | `NULL` | Moderator/admin attribution only; never inferred from composer text. |
| `created_by`, `created_at`, `id` | Provenance/system identity | Existing schema rules | Immutable through contribution enforcement; preserve recorded creators and do not backfill historical attribution. |
| Media/sheet-music links, lore, comments | Append-only community relationships | Not applicable | Keep their existing creator/author policies; they do not unlock canonical overwrites. |
| Personal notes/preferences | Per-user editable metadata | Existing table rules | Remain owner-editable and outside canonical contribution enforcement. |
