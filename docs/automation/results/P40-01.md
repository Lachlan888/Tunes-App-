## Targeted change and recheck

`lib/loaders/library.ts` now starts the bounded page/count reads alongside filter metadata and list names when no style filter is selected. Style-filtered reads still wait for resolved style IDs. It preserves the same search, count, cursor/page size, media, ownership and list-membership queries; query count and returned rows did not change in the observed search. No cache or freshness trade-off was introduced.

Two post-change traced `q=blackbird` requests kept one matching tune. Their `library.catalogue` elapsed times were 259 and 100 ms versus the 575 ms baseline; the latter warm request completed in 516 ms. The first post-change request took 2.0 seconds overall due to a 558 ms auth lookup and dev compilation. A third hit transient Supabase DNS `ENOTFOUND` and showed the existing retry state. After restarting without the temporary tracer, the same search rendered again, and `/library?style=Irish` rendered 20 of 21 fetched rows with its style filter. This supports the eliminated serial wait, not a guaranteed user latency reduction.
