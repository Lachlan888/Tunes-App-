# P33-04 — Day-by-day session schedule

Accepted 25 September 2026. Festival hubs now present programme sessions by festival-local day, and the owner Dev workflow supports reviewed session intake plus exact associations to existing public Lists. Festival mode remains Off; no production hub, session, list association, or setting was mutated.

## Acceptance

- Added a hub-only, horizontally scrollable day selector with native touch controls plus Arrow Left/Right, Home and End keyboard movement. Dates are formatted from stored local dates in UTC-safe calendar form, so a visitor timezone cannot shift the published festival day.
- Added deterministic chronological ordering: date, known start time, editorial order, then record ID. Overlapping sessions remain separate and stable; unknown dates and times remain explicit and sort last rather than being invented.
- Session cards show supplied changed/cancelled status, optional end time, leader and venue, an honest absent-list fallback, and exact links to associated existing public Lists. No new catalogue, saving, practice, or schedule destination was added.
- Public loading joins only visible session-to-collection associations whose source List remains public. Sessions held with `needs_review` continue to be excluded, and private source/review notes remain server-only.
- Extended the owner-only Dev panel to create or correct sessions, attach/reorder existing festival collections through the validated session action, retain source/snapshot notes, and default new photo-derived entries to **Hold for owner review**.
- Documented the intake workflow in the owner UI: supplied programme photo → visible-field draft entries → flagged ambiguities → owner corrections/list confirmation → explicit review-hold removal. No OCR service, model dependency, autonomous image publication, or fabricated programme data was introduced.
- Preserved the existing programme snapshot date, festival timezone and official-programme change wording from P33-03.
