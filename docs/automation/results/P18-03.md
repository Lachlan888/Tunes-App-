# P18-03 — Account isolation and offline recovery

Accepted 26 September 2026. The current stack keeps recovery deliberately conservative: an installable manifest is present, while no service worker caches private queues, notes, cross-user data or third-party media. Loaded pages, account-scoped session storage and safe URL state support temporary connection loss; writes remain disabled/retryable until online and server truth remains authoritative.

## Demonstrated defect and fix

The new disposable PostgreSQL harness reproduced one account-isolation defect before the fix: `formal_review_submissions` scoped idempotency by `(user_id, submission_key)`, but `review_events_review_submission_key_idx` was globally unique, so a second account using the same opaque key failed. Migration `20260926062804_scope_formal_review_event_idempotency.sql` keeps the event key indexed but removes global uniqueness; the per-account unique constraint remains authoritative. The harness then passed same-key replay (one event, prior result returned), cross-account rejection and independent same-key use by two accounts.

The reviewed migration was applied to the linked Tunes App project as remote version `20260926062937`. Read-only remote verification confirmed the event index is non-unique, `(user_id, submission_key)` remains unique, `complete_formal_review` remains security-invoker and `formal_review_submissions` retains RLS. Fresh security advisors reported no finding against the changed objects; existing unrelated advisor findings remain outside this slice. No production rows were written.
