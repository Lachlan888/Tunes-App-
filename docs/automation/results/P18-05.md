## Demonstrated defects and fixes

Fresh lifecycle execution exposed two real Reference Mode state regressions behind stale harness assumptions:

- On remount, the default loop-bank initialiser overwrote the account-scoped restored playback speed and loop state. It now selects the restored bank without replacing the persisted playback snapshot.
- Changing recording could allow the prior recording's draft loop to dirty and repopulate the new source's default bank. Initial banks now come directly from the new source's saved-loop props before any playback state is applied.
- Previous/Next selected a saved loop but left a different loop bank active, so a later save could update the wrong bank. Saved-loop selection now activates its matching bank, or loads the loop into the current bank when it is not already assigned.
- Successful Undo restored the server loop but left the active bank empty. Undo now restores the loop, bank, playback window, speed and edit state together.

The two disposable integration harnesses were updated from the retired playlist/editor labels to the current loop-bank and save-modal contracts. Their initial failures reproduced the state defects before the implementation changes.
