# P31-b — Host and join journeys

Accepted 24 September 2026.

The host sheet now displays the readable three-word alias returned by invite creation, offers a dedicated copy action, and never presents the long opaque token as the primary join code. QR generation and link sharing continue to use the opaque invitation URL. Regeneration updates both the private token and readable label, while cancellation clears both from component state.

The join form accepts case-insensitive words separated by spaces or hyphens and routes their canonical hyphenated alias to the existing join page. It retains compatibility with pasted legacy tokens. Invalid, expired, revoked and consumed states continue to use the existing explicit feedback; authenticated acceptance, profile requirements and repertoire consent remain unchanged. The join button now names its input `inviteCode` to accurately cover both alias and token routes.

Fresh automated coverage verifies the host alias display/copy contract, opaque QR path, join normalisation, alias/token loader branches, shared acceptance action, expiry/revocation lifecycle and legacy compatibility. `node --experimental-strip-types --test tests/compare-invites.test.ts tests/compare-experience.test.ts` passed 16/16. Scoped ESLint, `npx tsc --noEmit`, and scoped `git diff --check` also passed.

Per the user testing preference, live two-session functional testing and visual acceptance are user-owned and were not agent-verified; this does not block queue advancement. The database alias migration remains remotely verified as recorded in P31-a.
